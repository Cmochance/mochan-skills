# agy-cli-modify — Antigravity CLI 检索与执行提速规则

目标：在不牺牲准确率的前提下压缩模型往返回合（尤其高成本 Plan 调查阶段）、保持主会话上下文精简、规避终端阻塞与重复审批等待。若会话首帧已注入 `[workspace snapshot]`，直接据此定位仓库与源码目录，省去开局盲目 `ls` / `git status` 探路回合。

## 1. 代码定位、符号骨架与切片读取

- **先定位行号，禁盲翻与乱猜**：位置未知时禁止逐个打开文件试探；首轮使用 `rg -n --heading`（查文件名用 `rg --files`）并显式指定源码目录（如 `Sources`、`crates`、`src`），禁止无范围扫描大仓根目录或构建产物目录（`.build`、`target`、`node_modules`、`dist`）。
- **陌生大文件先拉符号骨架**：面对 `> 800` 行且改点不明的源码文件，禁止盲读前几百行；先用单条 `rg -n '^(pub |async )?(fn|struct|enum|trait|impl|class|func|extension|protocol|def|export) ' <file>` 抽出函数/类型行号骨架，再定向切片读取。
- **按目的区分 `read_file` 粒度**（对齐 CLI 单次 800 行 / 46KB 上限）：
  - **准备修改的文件**：`≤ 800` 行直接一次整文件读完，免去后续补读文件头 import/类型定义；`> 800` 行同轮并发读取「文件头 `1..60` 行 + 目标改动区间」。
  - **只读追踪 / 跨模块查调用链 / 大文件（`> 800` 行）**：禁止从第 1 行起按 800 行翻页；拿到行号后用 `StartLine` / `EndLine` 按**「命中前 25 行 + 命中后 150 行」**非对称切片，同轮并发读完所有关联命中点。
- **广域调研走 `research` 子代理隔离上下文**：需跨 `≥ 8` 个文件或多个子仓库大海捞针式只读摸底时，优先委托 `invoke_subagent(TypeName: "research")`，仅向主会话带回「文件路径 + 行号 + 核心结论」，防止数万行原始代码滞留主历史拖慢后续每轮重发。

## 2. macOS `zsh` 与检索防阻塞写法

- **本地沙盒检索与输出限流**：优先使用沙盒内毫秒级免审的 `rg`、`jq` 及管道限流（如 `| head -n 80`），防止单次输出超长触发落盘后再额外花 1 回合读取临时文件。
- **通配符强加单引号**：凡含 glob 的参数（如 `rg -g '*.swift'`、`git --no-pager diff -- '*.rs'`）必须用单引号包裹，规避 macOS `zsh` 默认 `NOMATCH` 在无匹配时报错中断、白费修复回合。
- **Git 禁分页挂起**：Git 查看命令统一加 `--no-pager` 与条数上限（如 `git --no-pager log -n 10`）。

## 3. 沙盒分层、静默构建与免审批前缀

- **纯沙盒内（`BypassSandbox: false`）合并与静默（Quiet-on-Success）**：编译、单测、lint、`git status/diff` 用 `&&` 或 `;` 合并单次执行；**编译与测试默认带原生静默参数**（如 `cargo check -q`、`cargo test -q -- --quiet`、`swift build -q`、`swift test -q`、`pytest -q`、`npm test --silent`），通过时接近零输出、失败时保留完整报错栈，防止编译/测试刷屏永久膨胀历史轨迹。
- **跨沙盒边界（`BypassSandbox: true`）**：严禁用 `&&` / `;` 将沙盒内准备/编译步骤与需联网/钥匙串/外部权限的命令混串；直接调用目标二进制（不套 `env`/`xargs` 包装、少用 `$(...)` 与变量展开），保护 CLI `"always allow"` 二进制前缀匹配。

## 4. 零中间废话与高信噪比回答

- **工具调用轮零过渡播报**：处于连续检索、读取或修改的中间回合时，直接发出工具调用，**不附带自然语言过程解说**（如“我先读一下某文件看看……”），消除无意义的流式生成延迟与历史注水。
- **结论先行、链接代贴码**：常规问答与执行汇报先给结论再列要点；引用已读代码一律用 `[basename](file:///绝对路径#L起-L止)` 替代原样大段贴回代码；常规回复控制在 1500 字以内。
- **场景豁免**：方案评审、Plan 交接计划、深度架构分析，或用户明确要求「详细讲 / 展开」时，完整展开不截断。
